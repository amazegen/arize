## Changes

- Bounded multi-batch draining: **100 claimed jobs/run by default**, configurable 20–500; default **8 workers**, configurable 1–8. Individual SQL claims remain capped at 20 and use existing row leases/`SKIP LOCKED`. The run has an 80-second work budget, reserves worst-case per-job/database time before claiming, and reports limit/budget stops. This replaces the old one-batch/20-job ceiling, not the per-day opt-in limit.
- SDK encryption/VAPID with native HTTPS and a **hard 5-second deadline**. Unlike socket inactivity, it aborts a stalled request. Destinations remain allowlisted, redirects/proxies are not followed, and provider bodies/endpoint-bearing errors are not retained. Unit tests use a fake HTTPS request factory; no provider requests were made.
- Database pause control defaults **off/paused**. Both claiming and fresh lease checks respect it. Provider 401/403 automatically pause future work; in-flight requests cannot be recalled. Invalid configuration fails closed. Storage/finalization uncertainty is marked partial/unconfirmed, not counted as confirmed sent.
- Protected, no-store `GET /api/notifications/dispatch` provides only aggregate queue/run health. It never sends. POST remains the sending method. Both require the existing independent 32+ character dispatch secret in the Authorization header, never a URL. No browser/user role can read the monitoring tables or run worker functions.
- Aggregate run records retain counters/stop reason/duration for 14 days, with no user IDs, subscription endpoints, keys or private content. `sent` means provider acceptance (or simulated acceptance in this receipt), not proof the device displayed it. Health includes pending/leased jobs, oldest due age, failed/expired jobs due in 24 hours and the latest run. Jobs never created during an extended scheduler outage are not counted as expired; monitor run gaps too.
- Fresh account checks exclude unverified, anonymous, banned, non-onboarded, deleting or no-longer-consented accounts from eligibility. A narrow private Auth helper replaces any need for broad Auth-table grants.
- Reminder management reuses the adult Phase 7 `native_session_context` ownership/expiry/MFA check, rejecting revoked JWT sessions. The prepared native-account migration must exist on a future approved target. A domain-separated HMAC binds card mutations to the verified user/session; a stale tab cannot silently attach a new subscription after an account switch. The binding lives in component memory, not analytics/storage/logs. It is not an authentication token; the verified session and same-origin checks are still required.
- UI reads current permission on mount/focus without prompting. Missing keys keep Enable disabled with an explanation; denied permission does not restrict Arize. Enabled status requires a live browser subscription and granted permission. Expired subscriptions do not appear enabled; explicit re-enabling renews them, and server registration removes expired owned devices before applying the five-device cap.
- Worker readiness targets Arize's registration rather than any service worker. Cleanup never unsubscribes an unrelated worker. Local unsubscribe still runs if server/account-binding reads fail. Real OS allow/deny tests have **not** been performed.
- `scripts/push-scheduler.mjs` is **dry-run by default**. It prepares one authenticated POST (or read-only health GET), not a recurring task. Execution requires separate adult-hosted approval switches and an exact canonical HTTPS target. No cron/job/provider subscription has been installed. No automatic retry occurs after ambiguous HTTP failures.
