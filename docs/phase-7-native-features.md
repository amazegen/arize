## Implemented

- Accounts: existing email/password sign-in, email-confirmed signup, same-device PKCE confirmation/reset callbacks, password replacement followed by sign-in, generic existing-account guidance, explicit legal setup, display name/username editing and sign-out. Verified TOTP accounts must complete MFA; other MFA methods fail closed rather than bypassing verification. Native Google sign-in wiring is present but disabled by default and not provider-tested.
- Sessions: refresh via the existing Supabase SDK, per-request verified bearer identity plus a real `auth.sessions` ownership/expiry check, revoked-session rejection even while an old JWT is otherwise valid, account-switch/late-response guards, foreground revalidation, background private-screen unmount and native privacy-cover source. No cookie fallback or weakening of the existing website's same-origin rules.
- Secure storage: iOS uses the app-scoped `ArizeKeychain` plugin with `WhenUnlockedThisDeviceOnly`, no iCloud sync or Preferences/localStorage token storage. First-install cleanup targets only this app's dedicated Keychain service. The actual scene root registers the plugin. Browser review uses per-client memory only; reloading requires sign-in and is not a persistent web login.
- Goals: existing adult records, current/prior weeks and day selection, add/edit/complete/remove. Completed goals remain grey with a check; add/edit and an identical retried create do not reset completion. Ownership and existing plan restrictions remain server/RLS-enforced.
- Clarity: explicit versioned AI-sharing choice, text chat, saved conversation list, reopen/continue/new chat, safe manual retry, local pending message, loading/error feedback and scoped auto-scroll. Conversation list pages are 50 for Plus; Core retains its existing three-conversation limit. Messages load in pages of **200**, with **Load earlier messages** preserving reading position. Message IDs use lossless bigint cursors; opening a long chat jumps immediately to the newest message. Generation context remains bounded to the latest 14 messages and 12,000 characters.
- Clarity security: web and native share the same adult configuration, locked prompt and input/output safety pipeline. Native history is server-owned; clients cannot submit system/assistant history. Durable existing plan quotas, per-request body hashes/leases (up to three generation attempts), checked-history atomic save and cached successful retry prevent a repeated send from creating duplicate saved turns. Crisis-blocked input is not persisted as ordinary conversation history. A fixed safety reply is not a counselor notification. No private prompts/replies, bearer tokens or raw SDK errors are logged by the native routes. No unchecked streaming/fallback was added.
- Village: authorized room list, join/leave, text sending, latest 50 messages plus earlier-page navigation, stable-ID retry, manual refresh and authorized Realtime subscription wiring/cleanup. The local model has no WebSocket service; it visibly falls back to manual refresh. Actual hosted Realtime delivery/reconnect remains unverified. Reconnect refreshes the latest page; it does not retain every older loaded page. No audio/video recording, upload, storage URL or playback is exposed; older media records render a text-only placeholder.
- Profile/deletion: membership status without native purchase/plan-change controls, existing generic on-device reminder controls, privacy/terms links and an explicit permanent-deletion form. Deletion requires a session created within 15 minutes, confirmation phrase and acknowledgement; it revokes sessions first and reuses the existing cancellation-before-data-removal workflow. Provider cancellation/storage failures stop completion; user can sign in and retry a pending deletion. No subscribed real account was deleted or canceled in testing.
- Bundled grounding remains available while signed out and from Home. The native package still loads bundled assets, not a hosted `server.url` shell.

## Server and database

Gateway: `/api/native/v1/{session,account,legal,ai-consent,goals,coach,village}`. Explicit adult edition + API flag, bounded JSON/field allowlists, exact CORS origins, no credentials/cookie fallback, private/no-store responses, verified email, legal/onboarding/MFA/deletion gates and owner-bound mutations. The mobile CSP permits only the configured adult API, Auth and Realtime origins; server secrets never enter its bundle.

Prepared migration: `supabase/migrations/20261122211346_native_adult_accounts.sql`. It refuses Student installation. `native_private` contains RLS-enabled AI choices and a service-only request ledger; browser roles have no direct table access. Public native functions are security invokers, with empty search paths and restricted execute grants. Private fixed-query security-definer helpers check Auth ownership/expiry without giving the application server broad Auth-table access. Tests explicitly revoke such fixture grants. The ledger stores a hash rather than unchecked input; completed entries contain the checked reply. Entries older than 14 days are pruned when that account next claims a turn, **not by an installed background retention job**. Account removal cascades native records.

Nothing was installed on hosted Supabase. Before future activation, apply/test this migration only on a separately approved **adult test target**, including permissions against the actual Auth schema. No hosted advisor result or compliance certification is claimed.
