# Adult Village safety — local implementation and acceptance

Prepared on `codex/phase-7-native-features`. No merge, push, deployment, hosted SQL/storage operation, Stripe action or Apple upload. Student checkout remains unchanged. Existing untracked audit notes are not part of this batch.

## Implemented

- Shared **Report message / Block author / Room safety** controls in adult web Village and the adult native/browser client. Native remains text-only. Reports use six fixed reasons, not free-text health information. A visible success acknowledgement explains that reports are not an emergency service or monitored live.
- Private report records, unique per reporter/message, with server-enforced membership/plan/verified-account checks. A blocked or hidden message cannot be newly reported by an unauthorized reader. Reporters are not identified in the moderator queue.
- Account-owned bilateral blocks across Village rooms. Both sides' messages are filtered by restrictive database row policies; this is not just CSS or a local preference. Unblocking is available under Room safety. Sharing a room remains possible. Previously delivered/downloaded content cannot be recalled.
- Explicit **per-room** moderator assignments in `village_safety_private.moderators`. First join no longer grants moderation. Legacy `is_moderator` values and the old peer-promotion RPC do not grant new safety authority. No real person is assigned by the migration. Native APIs additionally enforce the existing verified session/MFA/setup checks; the public safety RPC also requires AAL2 when a verified MFA factor exists.
- Room safety → Review reports: up to 50 prioritized report records in the assigned room, with hide, dismiss, restore, mute author for 24 hours and unmute. Hiding is reversible, not deletion. Mutes expire automatically. The queue exposes reported Village text/metadata only, not Clarity or Student data. Decisions append actor/time/room/message/action audit records. The native queue does not play audio/video; media evidence review remains an operator workflow outside this text-only UI.
- Database insert trigger serializes each sender's writes across rooms. It enforces a **2-second cooldown, 10 posts/minute, 120 posts/hour**, normalized duplicate-text rejection for 10 minutes, and 1–4,000 character content. Client timestamps are replaced with server time. Matching-ID retries still reach the existing idempotency handling. Report creation is capped at **5 new reports/hour**; a duplicate report does not consume another slot. These limits apply to authenticated message writes, not a blanket account/IP/storage-upload quota.
- Private Village media bucket and 60-second signed links, checked against room membership, plan, hidden-message state and bilateral blocks. Legacy managed public paths remain usable through authorized signing; arbitrary external media URLs are not rendered. Existing files are not moved/deleted. Already issued signed URLs can remain usable for their TTL; cached/downloaded copies cannot be recalled. Hosted CDN behavior still requires rollout verification. No live bucket was changed.
- Active rooms recheck the latest message page every 15 seconds and on foreground/visibility/reconnect; own safety actions refresh immediately. Old native visits and out-of-order fetches are guarded. This is bounded revalidation, not instant remote recall; background clients refresh on return. Refreshing reloads the latest page, rather than preserving every earlier loaded page.
- Failed web text sends retain the draft and show safe errors. Raw provider errors and external media URLs are not logged/rendered. Shared React is deduplicated in Vite; the browser test caught and verified the fix for the initial duplicate-React crash.
